# AIA2 Machine Guard — 0.2.0-alpha

Це вихідний код допоміжного моду NeoForge 21.1.264 для Minecraft 1.21.1 / Java 21.
Він додає перевірку перед стандартним серверним викликом `BlockEntityTicker.tick`.
Якщо епоха блока ще закрита для команди-власника, машина не отримує цей виклик,
зокрема не виконує рецепт, збережений у її внутрішньому кеші. Окремі Mixin
перевіряють результат vanilla-крафту 2×2/3×3 до взяття предмета, включно з
quick move, та результат vanilla Crafter до видачі предметів і витрати сировини.

Це перевірка епохи **самої машини**. Рецепт пізнішої епохи в машині ранньої
епохи потребує окремого адаптера. Переміщені конструкції Create, сутності,
заплановані тики інших блоків та прямий обмін через capabilities не проходять
цей перехоплювач. Власні crafting-меню модів, smithing, stonecutter та результати
переплавлення не охоплені перевіркою vanilla crafting-слотів. Він також не
доводить виробництво предметів для квестів.

Власник зберігається в `BlockEntity.getPersistentData()` під ключем
`aia2_guard_owner_team`; звичайний міст не може перепризначити іншу команду.
Правила `blockGates` беруться з `kubejs/config/aia2_runtime.json` до запуску світу.
До завантаження підтвердженого прогресу всі машини епох 2–48, creative та
карантину зупинені. Невідомий блок моду отримує карантин 100; звичайні vanilla
блоки без окремого правила залишаються доступні. Відомі правила 0–1 не
потребують власника. Міст KubeJS повинен спочатку передати правила блоків та
предметів, всі командні записи, UUID поточних гравців, а потім викликати
`setReady()`. FakePlayer не може брати staged-результат через player crafting;
для Crafter використовується команда-власник блока. Результат перевіряється
сервером; client-інтерфейс не є джерелом дозволу.

Перед кожним staged-крафтом мод читає поточну команду через публічні API
FTB Teams та порівнює її з підтвердженою командою мосту. Кешуються лише
рефлексивні методи. Після зміни команди старий дозвіл одразу непридатний;
якщо API недоступне або повертає помилку, staged-крафт залишається закритим.
FTB Teams не потрібен для компіляції чи самого запуску моду, але потрібен
для підтвердження команди під час такого крафту.

API: `Java.loadClass('ua.aia2.guard.Aia2MachineGuard')`, статичні методи
`clearRuntime()`, `setRulesJson(json)`, `setItemRulesJson(json)`,
`setTeamProgress(team, completed)`, `setPlayerTeam(uuid, team)`,
`setReady()`, `isLoaded()`, `isReady()`, `getRequiredStage(blockId)`,
`getOwner(blockEntity)`, `setOwner(blockEntity, team)`, `mayCraft(player, output)`,
`mayProduce(blockEntity, output)` та `getDeniedTicks()`.
Перевірку прав гравця перед `setOwner` виконує серверний скрипт.

Збирання на комп'ютері з JDK 21 і доступом до репозиторіїв NeoForge/Mojang:

```sh
./gradlew build
```

Результат: `build/libs/aia2-machine-guard-0.2.0-alpha.jar`; його потрібно
покласти в `mods/` інстансу. Поточний скомпільований JAR уже додано до
кореневого `mods/` репозиторію; точні результати перевірок наведено у `verification-report.json`.

`./gradlew policyTest` або `python test_policy.py` з налаштованим `JAVA_HOME`
перевіряє чисту Java-політику. Цей тест не запускає гру
та не підтверджує застосування Mixin. Конфігурація Mixin має `required: true`
та `require: 1`, щоб несумісна точка перехоплення спричинила видиму помилку
запуску замість непомітного вимкнення захисту.

Dev-конфігурація `runServer` додатково вмикає `aia2.guard.verifyMixin=true`:
завантажує п'ять цільових класів та перевіряє застосування Mixin через marker
interfaces ще до створення світу. Це перевірка прив'язки перехоплювачів,
а не тест фактичного крафту, машини чи повної збірки.

У перевіреному запуску dev-режим Minecraft автоматично пропустив перевірку
EULA та створив тестовий світ; сервер зупинено після виявлення цього.
Файл `eula.txt` не створювався і вручну не приймався. Це поведінка dev-режиму,
а не підтвердження умов для інстансу користувача. Повна збірка та реальні
сценарії крафту/машин у цьому запуску не перевірялися.
