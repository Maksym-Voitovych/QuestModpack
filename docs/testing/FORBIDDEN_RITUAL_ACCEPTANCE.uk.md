# Forbidden Arcanus 2.6.1 — приймальна перевірка 0.4.12

Повний інстанс користувача в хмарі не змонтований. Модельовані Java-hosts,
мінімальний Minecraft і реальний Forbidden runtime — різні рівні перевірки.
Наведені нижче сценарії повного модпаку поки **NOT RUN**.

На тестовій копії встановити matching JAR/скрипти0.4.12 на клієнт і сервер,
повністю перезапустити, перевірити `/aia2 status`. Старі завершені епохи й
96виробничих ключів не мігруються заново. До оновлення бажано завершити
активні старі Forge-ритуали: вони ще не мають нового доказу оплати.

1. **Завантаження.** Перевірити weaving трьох Forbidden mixins без injection
   errors; усі140глав, українські тексти, Mundabitur-іконку старого Forge-квесту
   й16новихцілей. Наступні епохи лишаються заблокованими за своїми правилами.
2. **Власник і запуск.** Призначити кузню дозволеній команді через ПКМ.
   Невідома/чужа команда й FakePlayer не запускають ритуал. Ранній output,
   заборонений tier, ключ, змінений main/pedestal або stale enhancer cache
   не повинні списувати есенції чи створювати новий активний ритуал.
3. **Нормальний цикл.** Провести Ferrognetic Mixture, підвищення tier2–5
   й Eternal Stella на відповідних епохах. Перевірити, що останній тік із
   native counter `duration+1` завершується один раз, фізичні входи витрачені,
   вихід/блок правильний, owner кузні переживає upgrade.
4. **Досягнення.** Online-ініціатор має бути у вимірі кузні під час завершення.
   Шість advancement-цілей реагують на native `ritual_completed` із точним
   `recipe_id`. `/give` виходу не створює цієї події. Native trigger передує
   world effect/output; він не доводить успішного прийняття результату.
5. **Reload.** Почати оплачений ритуал; перезавантажити тотожне визначення:
   поточний holder переприв'язується без повторного списання. Змінити duration,
   склад або output, прибрати визначення: прогрес має зупинитися, raw active
   NBT/receipt залишитися. Відновити точне визначення й фізичні входи: цикл
   продовжується. Окремо змінити enhancer registry і оновити його слот.
6. **Restart.** Повторити попередній сценарій із повним перезапуском світу,
   у тому числі коли native codec не знаходить ID ритуалу. Під час load
   `failRitual` не повинен викидати main stack або чистити п'єдестали.
7. **Фізичні входи.** Змінити count/components main або п'єдесталу під час
   paid-циклу; перевірити pause, відсутність output і збереження counter.
   Повернути точні предмети. Перевірити native cache із SINGLE_ITEM_CODEC
   після restart при фізичних stack count>1.
8. **Автоматизація.** Подати труби/воронки/fake-player/AE2 у кузню: пізні
   essence-input items і ключі не повинні перетворюватися на есенції через
   slots5–8. Ритуал потребує синхронізованого справжнього стартера. Цей hook
   не заморожує збір крові/душ із довкілля та сторонні API.
9. **Legacy/corrupt.** Завантажити копію старого активного ритуалу без receipt
   і копію з пошкодженим receipt. Вони мають лишитися збереженими й paused,
   без автоматичного «доведення» старої оплати новим визначенням.
10. **Діагностика/явне відновлення.** Біля своєї кузні виконати
    `/aia2forge status <x> <y> <z>`. Оператор власної команди може явно
    виконати `/aia2forge cancel <x> <y> <z>` у радіусі8блоків. Скасування
    зберігає receipt/raw snapshot у persistent NBT кузні
    `aia2_fa_cancel_backups_v1` (максимум8), прибирає активний процес та
    індикатор, залишає всі фізичні входи. **Есенції не повертаються, output
    і квестовий доказ не видаються.** Заповнений або пошкоджений backup
    не перезаписується. Це ручний вибір оператора, інсталятор його не робить.
11. **Межі.** Clibano-квести цього блоку перевіряють підготовку/видиму панель,
    а не власника внутрішнього main controller і повний виробничий цикл.
    Окремо перевірити Obelisk, предметні здібності, сторонні ritual result
    types, копійовані компоненти й transitive registry/tag changes.
12. **Навантаження й баланс.** Виміряти TPS з одночасними кузнями; перевірити
    JEI, нагороди, подачу ресурсів Survival і весь перехід епох із двома
    справді виготовленими ключами. У хмарі TPS-оцінки немає.

Змінені/непідтверджені платні операції призупиняються зі збереженням стану.
Це не універсальний rollback: native RNG, midpoint lightning/pedestal effects
та витрати до output можуть уже відбутися. Native essence modifiers/raw-cost
семантика збережена: reduce RETURN доводить виклик списання, а не математичну
рівність зниженої перевірки й фактичних raw-витрат. Глобальний reset AIA2
не очищує це NBT-сховище.
