# CCA/CDG0.4.23 — приймання повного інстансу

Повний клієнт, original optional binary dispatch, JEI, Survival і TPS: **NOT_RUN**.
Це план перевірки на окремій тестовій копії; модельовані43helper/handler checks
і source facts не замінюють роботу встановлених аддонів.

1. Зупинити гру й сервер, резервувати інстанс і світ. Створити незалежну копію
   без Junction на оригінал. Установлювати пакет спочатку через `--dry-run`.
   Перевірити backup старого власного JAR, незмінність світів/TeamData та
   сторонніх файлів. Повторне встановлення повинно бути ідемпотентним.
2. Після повного restart перевірити `/aia2 status`, required Machine Guard,
   відсутність AIA2 KubeJS errors. Установлений CCA має бути1.6.0, CDG має бути
   1.21.1-1.3.15; зафіксувати SHA фактичних JAR. У mechanics config тепер16
   правил:15попередніх і `cca_electrum_mixing`. Старі key/NASA/station receipts
   та paid pending transitions не повинні змінитися.
3. Перевірити3396квестів/140глав/6груп і15нових optional-цілей двох аддонів у
   «Автоматизації». Переглянути приховування/блокування епох11/12/15/18,
   українські назви, іконки й лінії. Старі ID/tasks/rewards/deps зберігаються;
   нові цілі не стають новою умовою старих ключів. Візуальна перевірка тексту
   та масштабу потрібна додатково до статичного layout.
4. У підготовленій тестовій команді після відкриття відповідних залежностей
   виготовити11типів звичайних компонентів із `only_from_crafting:true`.
   Перенесений старий предмет і `/give` не повинні зараховувати ці tasks.
   Крафт до відкриття залежностей не має ретроспективно створювати прогрес:
   повторити операцію після відкриття. Перевірити звичайний і shift-click крафт.
   Механічний крафт, Rolling Mill та fluid outputs не підміняють crafting event.
5. Для команди з доступом до епохи15 привласнити справжній Basin через звичайне
   встановлення власником. Виконати `createaddition:mixing/electrum` з реальними
   gold+silver inputs, прийнятим виходом і нагрівом. Очікується2уніфіковані
   `immersiveengineering:ingot_electrum`, новий командний receipt і проєкція
   `aia2:mechanics/cca_electrum_mixing`; окремий item task перевіряє2зливки.
   Доказ зберігається після reload і restart. Інша команда його не успадковує.
6. У нових тестових командах перевірити негативні випадки: лише предмети або
   `/give`, IE alloy recipe замість точного CCA recipe, симуляція, недостатні
   inputs/heat, заблокований вихід, чужий/непривласнений Basin, epoch14 замість15.
   Вони не повинні створювати новий receipt. Наявний старий proof не підходить
   для негативного сценарію: для кожного випадку потрібна нова команда/копія.
   Рання робота нагріву через CDG Burner можлива; обраний новий quest contract
   має floor15 і не заявляє, що це абсолютно найраніший нагрів у збірці.
7. Звірити в JEI справжні продукти: ingot→rod і plate→wire; два рецепти capacitor
   є варіантами одного компонента, не рівнями акумулятора. Перевірити мотор:
   POWERED зупиняє його; для relay POWERED дозволяє transfer. Tesla charging,
   accumulator charge і contraption interface перевірити вручну: inventory та
   observation не вимірюють FE/t або фактичний потік.
8. Для CDG перевірити ефективні server config/fuel data та теги: Sugar Cane
   входить у fermentable, Wheat не підміняє його; plant oil і CCA seed oil
   мають перевірений спільний tag.400processing_time є базовим параметром,
   а не гарантованими400wall ticks для Bulk Fermenter. Вежа потребує одного
   контролера на кожен tank block; default minimum height3 може змінюватися
   конфігом.4контролери/4tank із квесту не обіцяють повну вежу довільної форми.
   Для Mold потрібен правильний `mold_type`; generic item task не доводить форму.
9. Перевірити нагороди: невеликі матеріали CCA або wood chips CDG, без готових
   обов’язкових машин/ключів/майбутніх ресурсів. Buckets і огляд обладнання
   не є доказом native fermentation/distillation, оплати рідин або автоматизації.
   Зберегти actual client logs і результат кожного сценарію окремо; не переносити
   негативні фікстури або навмисно пошкоджені журнали в оригінальний світ.
