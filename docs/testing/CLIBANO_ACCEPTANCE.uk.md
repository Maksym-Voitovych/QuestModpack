# Clibano2.6.1 — приймальна перевірка0.4.13

Ці сценарії повного модпаку поки NOT RUN. Запускати на копії світу з
matching0.4.13 JAR/скриптами; Windows-інстанс у хмарі не змінювався.

1. Завершити стару активну плавку, встановити оновлення з backup/dry-run,
   перезапустити клієнт і сервер. `/aia2 status` має показати API4 active.
   Перевірити завантаження3351квесту/140глав і всі попередні completed IDs.
2. Сформувати Clibano. До першого дозволеного ПКМ внутрішній main не повинен
   виробляти як unowned. Натиснути рамку своєю командою: owner має бути на
   main і26частинах. Сусідня піч, чужі owners, fake/spectator, інша епоха,
   захищена або незавантажена частина не повинні давати owner/menu.
3. Розмістити дві близькі печі: відкривається main саме clicked-frame,
   а не найближчий POI. Змінити FTB-команду/стадію з відкритим GUI:
   наступні серверні операції контейнера мають відхилятися, меню закривається.
   Замінити main новим блоком на тій самій позиції з тим самим owner: старе
   меню не повинно працювати зі старим handler; нове відкривається окремо.
4. Виконати три реальні рецепти: Arcane Crystal→Dust, Runic stone-family→Rune,
   Raw Iron+Obsidian+ArtisanRelic→Obsidiansteel. Звичайний FIRE дозволений;
   enchanted flame не є вигаданою умовою сплаву. Перевірити прийняття виходу
   й точне списання одиниці з відповідної лінії/обох ліній.
5. Перевірити3командні proof-квести. `/give`, нагорода або предмет з іншої
   машини не зараховують цикл. Інша команда не отримує proof. Після restart
   й входу гравця командне SavedData має відновити проєкцію advancement.
6. Холодна піч без палива не просуває лінії. Duration1 тестового рецепта
   не дає output до оплати. Зупинка горіння зберігає наявний прогрес;
   повернення палива дозволяє продовжити.
7. Запустити дві різні лінії, заповнити виходи. Завершення першої не стирає
   другу. Окремо додати перекривний тестовий рецепт: native polling queue
   не підміняє вже перевірений план другої лінії. Перевірити component-aware
   заборону злиття з однойменним, але іншим результатом.
8. Під час роботи виконати reload тотожного рецепта, потім зміненого або
   видаленого. Тотожний продовжується; інші pause до нового списання/зміни
   прогресу. Повторити після повного restart, з legacy/corrupt receipts.
   Дані не повинні автоматично стиратися або отримувати новий доказ.
9. Накопичити residues. Current-holder/result policy має діяти перед
   конверсією. Видалений holder/unread raw data й неправильні cooking arrays
   не повинні ламати відкриття GUI. Історію попереднього residue definition
   через зміну datapack не вважати доведеною.
10. `/aia2clibano status x y z` — біля своєї цілісної печі. Operator-only
    `cancel` має зробити bounded8backup і скинути лише lane-progress/receipt;
    усі7слотів, residues, burnTime/soulTime збережені, refund/output/proof0.
    Дев'ятий або пошкоджений backup не перезаписується. Перевірити відмову
    чужому/далекому оператору. Це явне ручне відновлення, не автоматична міграція.
11. Перевірити ресурси/іконки/українські тексти/JEI і проходження Survival.
    Capability IO через рамку не заявлено: upstream forwarding закоментовано.
    Виміряти TPS при багатьох активних печах; модельовані тести не є benchmark.
