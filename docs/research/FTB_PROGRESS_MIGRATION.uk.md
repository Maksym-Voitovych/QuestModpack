# FTB Quests 2101.1.36 — збереження прогресу під час міграції

Досліджено source pin `8c53f35a97d8897c861b097f1e39f4fc3beb3a15`.
Точні SHA п’яти source/version файлів і офіційні GitHub-посилання збережено
в `content/research/evidence/required_space_v10/ftbquests/task-progress-facts.json`.
Це API-факти за pinned джерелом; оригінальний встановлений binary не надано.

`TeamData` зберігає числовий `task_progress` і completed timestamps за ID.
Тип завдання й джерело підтвердження до цього запису не входять.
Старе завершення не переоцінюється автоматично при заміні умов.
`AbstractBooleanTask` має max1; якщо старий item progress уже дорівнює1,
`setProgress(1)` може не змінити значення й не викликати завершення.
Результат — успадкований completion або100% без timestamp. Стабільний ID
сам по собі не робить заміну item→advancement сумісною.

У0.4.21 типи й payloads усіх старих завдань збережено. Чотири наявні NASA-цілі
отримали явний required overlay, а їхні нативні командні receipts додатково
перевіряються Java і KubeJS незалежно від FTB. Інсталятор зливає визначення
за ID та зберігає чужі квести; він не редагує TeamData, світи чи їхній прогрес.

Уже завершені епохи не скидаються. Старі оплачені pending без маркера
завершуються за попереднім контрактом і все ще потребують обидва нативні
key receipts. Нові37/38pending зберігають marker1 й перевіряють NASA після
перезапуску. Жодна міграція не надає безкоштовних предметів, receipts чи стадій.
