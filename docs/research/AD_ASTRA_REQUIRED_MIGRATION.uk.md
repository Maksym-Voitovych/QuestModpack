# Обов’язковий маршрут Ad Astra — сумісна міграція 0.4.21

У попередній версії всі чотири перевірені NASA-збірки були optional.
Обов’язкова технологічна гілка могла завершуватися через старі предметні
завдання. Тепер наявні цілі T1–T2 включено до технологічного ключа37,
T3–T4 — до ключа38. Разом із підготовчими залежностями обов’язковими стали
21 попередня ціль. Жодних нових квестів, рецептів чи предметів не створено.
Шість цілей будівництва станцій залишаються необов’язковими.

Історичний каталог `v5_nasa_manufacturing.json` не переписується. Явний overlay
у `v5-quest-content-migrations.json` вказує точний перехід required:false→true
та пояснення для чотирьох цілей. `v10-space-required-migration.json` фіксує
попередні payloads, ID, SHA каталогу, список21цілі та версію контракту.
`v5-migrations.json` описує точні старі й нові залежності чотирьох вузлів:
два підсумкові випробування й два технологічні ключі. Старі залежності не
видаляються; нові не посилаються назад із батьківської віхи на її нащадка.

Типи, кількості, умови та ID всіх старих tasks залишені. Це необхідно для
збереження числового FTB-прогресу: item→advancement на тому самому ID може
успадкувати completion або застрягнути на100%. Деталі й джерела —
[FTB migration](FTB_PROGRESS_MIGRATION.uk.md).

Java `RequiredSpaceActions` читає існуючий командний NASA-журнал незалежно від
FTB-прапорців, предметів та старих key receipts. Перевірка діє в нативному
`KeyProductionBridge.mayProcess` до виробництва й повторно перед записом
key receipt. Скрипт перевіряє докази перед готовністю гілок і витрачанням
ключів через `/aia2 key`. Старі виробничі записи не стираються й не
перетворюються на NASA-докази. Магічна гілка не отримує вимоги ракет;
інші46епох не отримують нового контракту.

Для поточного ключа37 потрібні `nasa_tier_1_rocket` і `nasa_tier_2_rocket`
поточної команди; для38 — T3 і T4. Ці докази вже реалізовані попереднім
NASA adapter: прийнятий світовий вихід і точна оплата14вхідних слотів.
Це не перевірка польоту, заправлення або побудованої станції.

Завершені епохи й платне відновлення останнього артефакту grandfathered.
Уже оплачений старий `pending` без `pendingActionContract` завершується за
попереднім контрактом: обидва нативні key receipts, старі milestones/trial
та фінальний квест. Він не чекає нового branch-key timestamp, який могли
заблокувати додані залежності. Повторної оплати чи створення NASA-доказу немає.
Новий оплачений37/38pending містить `pendingActionContract:1`; він зберігає
цю вимогу після перезапуску й не завершується без NASA-доказів. Невідомий
або orphan marker відхиляється без скидання журналу.

Додатково виправлено читання `aia2_mechanics_v1`: vanilla може проковтнути
помилку SavedData й повернути null. Тепер existing unreadable file та
несумісне NBT створюють blocked стан у пам’яті. Читання не встановлює
порожній журнал, blocked save заборонений; правильна схема1/історичні ID
залишені. Новий журнал записується лише після фактичного нативного завершення.

Повний Ad Astra/FTB/KubeJS клієнт ще не запускався. Модельні native hooks,
справжній Rhino та мінімальний Minecraft-сервер мають різні межі доказів.
Ручне приймання: `docs/testing/SPACE_REQUIRED_ACCEPTANCE.uk.md`.
