# 0.4.19-alpha — оплата й розміщення станцій Ad Astra

База: `56f07e5` / 0.4.18-alpha. Це окремий підблок розробки 0.5.
Повний модпак, оригінальний Ad Astra JAR і Windows-інстанс не запускалися.

## Виправлення

Нативний `SpaceStationRecipe.matches` окремо рахував усі слоти для кожної
вимоги. Один матеріал міг задовольнити кілька overlapping ingredients.
Потім `consumeIngredients` списував лише перший matching stack: за вимоги64
зі стеків1+63 витрачалася одна одиниця. Packet ігнорував результат
`placeInWorld` і далі реєстрував станцію та телепортував гравця.

Тепер точний `Type.handle(record): Consumer<Player>` обгорнутий одноразовим
серверним scope з `try/finally`. Synthetic lambda-назви не використовуються.
До оплати перевіряються справжній живий ServerPlayer, потік сервера,
синхронізована поточна FTB-команда й відкрита орбіта. Creative, Spectator,
FakePlayer і старі командні привілеї не дозволяють будівництво.
Нативні перевірки меню, ракети, планети, наявної станції та Cadmus збережені.

Глобальний bounded max-flow план розподіляє інвентар між усіма вимогами.
Кожна одиниця використовується один раз; constrained ingredient може
перепризначити альтернативу, тому greedy false negative не виникає.
Нативний `Inventory.removeItem` виконує точні списання з усіх потрібних слотів.
Після кожного списання перевіряються початкові refs, кількості, компоненти,
рецепт, поточні теги, команда й доступ до фактично витраченого матеріалу.

Підтримано до64 слотів/вимог, до4096 одиниць у кожній і до16384 сумарно.
Для оплати використовуються дозволені матеріали зі стандартними компонентами.
Перейменовані/нестандартні компоненти не витрачаються. Сторонні предмети
інвентарю не стають платою. Старі кеші `Ingredient#getItems()` не є доказом
поточного складу тегів. Майбутні альтернативи тегів залишені, але їх не можна
використати раніше власної стадії.

## Прийняття структури

До списання перевіряється існування структури через `get(id)`, без створення
порожнього fallback. Підтримана нативна single-palette структура без entities
і block NBT; межі64 по осі,65536 клітин/об'єму. Реальна структура має
31×32×31,30752 клітини та1151 non-air блок. Координати унікальні й у межах;
порожні, all-air, custom subclasses та інші непідтверджені форми відхиляються.
Знімок читає перевірені Minecraft-поля до будь-якої серіалізації.

Common Mixin спостерігає саме первинний `ServerLevelAccessor.setBlock`,
ordinal1. Для кожного non-air блока потрібні нативний `true`, точний запитаний
початковий стан і одноразова відповідна координата. Синхронні neighbor updates
всередині setBlock можуть одразу змінити властивості; після виклику
перевіряється той самий тип блока. Після native shape updates
перевіряється збереження всіх відповідних типів блоків, дозволяючи легальні
зміни властивостей форми/води. Це не перевірка остаточної повної рівності BlockState.
Поточні визначення структури й матеріалів повторно перевіряються перед реєстрацією.

`placeInWorld=false`, нуль прийнятих блоків, часткова відмова або зміна контексту
переривають packet до реєстрації, teleport і claims. Прямий unscoped constructor
не реєструє нову станцію; звичайні unscoped structure placements делегуються
без зміни поведінки. Старі native station SavedData не переписуються.

Операція не атомарна. Якщо callback відмовляє після оплати чи частини writes,
виконані ефекти залишаються; refund/rollback не вигадуються. Якщо стан змінено
всередині вже виконаної нативної реєстрації, її запис зберігається, але подальший
teleport/claims припиняється. Для destructive-тестів потрібна копія світу.
