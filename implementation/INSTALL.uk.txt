AIA2 0.4.12-alpha — встановлення та перевірка оновлення

1. Закрийте Minecraft і сервер. Збережіть окрему копію свого інстансу та
   світу: інсталятор резервує змінювані файли, а не весь світ.
2. Оновіть локальний Git checkout зі збереженням власних правок або
   розпакуйте AIA2-runtime-0.4.12-alpha.zip в окрему папку. Не накладайте
   старі ручні виправлення uuid()/getUUID() на нові скрипти.
3. У папці пакета/репозиторію виконайте:
   python -m pip install nbtlib==2.0.4
   python install_runtime.py "C:\CurseForge\AllInOneAdventure2" --dry-run
4. Перевірте перелік змін. Потім застосуйте:
   python install_runtime.py "C:\CurseForge\AllInOneAdventure2"
   H:\CurseForge\Instances\All in One Adventure 2.0 — Junction на той
   самий інстанс; повторно через H встановлювати не потрібно.
5. Інсталятор резервує всі змінювані оригінали ДО першої заміни, зливає
   групи та невідомі квести, зберігає data.snbt/світи/командний прогрес.
   Старий власний aia2-machine-guard-*.jar переноситься в backup перед
   заміною на 0.4.12-alpha; сторонні моди не видаляються. Збережіть шлях
   backup і journal.json, які виводяться після встановлення.
6. Для клієнта й окремого сервера встановіть однакові runtime-файли.
   Оновіть JAR і скрипти разом. Повністю перезапустіть обидва:
   /reload не замінює завантажений JAR і не додає startup-предмети.
7. Не копіюйте додатково старі ручні epoch_keys.js/epochs_01_06.js:
   дублювання реєстрацій або рецептів викликає конфлікт. Сторонні скрипти
   автоматично не видаляються; перед міграцією перевірте їх вручну.
8. Виконайте /aia2 status. Нормальний стан: активний Machine Guard API 4,
   завантажені правила й правильна епоха команди. Ініціалізація починається
   з серверного тіку після запуску, а тимчасова неготовність FTB має
   обмежені повторні спроби. За помилки перевірте показані фазу та причину.
   Після усунення причини оператор може виконати /aia2 guard retry.
   Ця команда не виправляє старий JAR: його потрібно замінити й повністю
   перезапустити гру/сервер. Не вимикайте required-режим захисту.
9. Виконайте /aia2 sync. Новий гравець починає з епохи 1. Завершені
   старі епохи зберігаються й не потребують повторних двох ключів.
   Для наступного незавершеного переходу:
   - завершіть обов'язкові технологічну й магічно-дослідницьку гілки;
   - реально виготовте два різні ключі за рецептами JEI;
   - дочекайтеся зарахування обох виробничих квестів;
   - біля звичайного верстака виконайте /aia2 key;
   - завершіть фінальний квест переходу.
   Команда витрачає обидва ключі та попередній артефакт; у першій епосі
   попередній артефакт замінено верстаком. Наступна стадія відкривається
   лише після фінального підтвердження, не від самої наявності артефакту.
10. /give або Creative-предмет не створює нативний запис виробництва.
    За втрати останнього законного артефакту використайте /aia2 recover:
    збережено попередню платну формулу, нова епоха не відкривається.
11. Старі/імпортовані машини без власника натисніть ПКМ дозволеним гравцем,
    щоб призначити команду. Машину з власником відвідувач не перепризначає.
    Перевірте роботу після виходу всіх членів команди й перезапуску.
12. На тестовій копії перевірте відмову ранніх крафтів, дві команди,
    автоматизацію ключів, підроблений ключ, українські назви, JEI та іконки.
    Сценарії й межі: design/progression-v4.md та KNOWN_LIMITATIONS.uk.txt.

Інсталятор не встановлює решту модпаку. Повний Windows-інстанс, додаткові
Create/Mekanism/AE2 перехоплення, клієнт і TPS потребують перевірки у грі.
Порядок резервування/відкату: INSTALLER-SAFETY.uk.md.
Інструкція та команди тестування: README.uk.md у корені репозиторію.

Поточний пакет — проміжна розробка0.5 на runtime0.4.12, а не завершена0.5.
Після оновлення перевірте чотири нативні виробничі докази (Create4/10, Mek16/23),
/give не зараховується. До ранньої латуні застосовується незагрітий рецепт AIA2.

Додаткові сценарії MI/Oritech/Roots: docs/testing/INDUSTRIAL_NATIVE_ACCEPTANCE.uk.md.
Нові native guards потребують саме matching0.4.12JAR; старийAPI4JAR не достатній.

EnderIO/Powah acceptance: docs/testing/ENERGY_NATIVE_ACCEPTANCE.uk.md.

0.4.12 Fire Crafting: епоха19, sneak+правий клік кресалом по ВЕРХНІЙ грані основи; потім звичайне запалення. Старі основи потрібно зареєструвати один раз. Згасання bedrock-вогню не скидає власника; заміна основи скидає. Worksite SavedData ніколи не видаляється інсталятором. Див. docs/testing/FIRE_WORKSITE_ACCEPTANCE.uk.md.

ProjectE0.4.12: matchingJAR обов’язковий для current-output/TimeWatch guards. Whitelist має14звичайних матеріалів; палива/матерія не синтезуються з EMC. Наше оновлення не очищує знання/EMC гравців. Приймальна перевірка:docs/testing/PROJECTE_DRACONIC_ACCEPTANCE.uk.md. Draconic CI633 provenance залишається BLOCKED; точний binary не тестувався.

0.4.12: passive inventory/armor/Curios/bag/chest/pedestal/packet guards і таблетка Curios47. Перевірка matching JAR містить класи та реєстрацію mixins. Приймальні сценарії: docs/testing/PROJECTE_PASSIVE_ACCEPTANCE.uk.md. Предмети, знання/EMC та збереження додатково не очищуються. Клієнтський Gem-рух і повний optional dispatch потребують гри.

EvilCraft0.4.12: matching JAR обов’язковий для infusion/spirit output guards. Spirit Reanimator і Sanguinary Accumulator складаються в Create5×3; JEI/головні матеріали збережено.16нових optional goals, native Closure capture. Manual acceptance:docs/testing/EVILCRAFT_CORE_ACCEPTANCE.uk.md. Forbidden ritual guard ще не реалізовано; див.source-audit.

0.4.12 — Forbidden Forge:
За можливості завершіть старі активні ритуали до оновлення. Без нового
receipt вони зберігаються paused; інсталятор не видаляє їх і не приписує
оплату. /aia2forge status x y z показує стан своєї кузні поруч. Оператор
може явно виконати cancel на тестовій копії: максимум8NBTbackup, фізичні
входи збережено, есенції не повертаються й результат не видається.
План повного тестування: docs/testing/FORBIDDEN_RITUAL_ACCEPTANCE.uk.md.
