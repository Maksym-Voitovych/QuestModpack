AIA2 0.3.0-alpha — межі перевірки

Перевірено окремо: синтаксис JS, справжній Rhino build.85 із моделями API,
SNBT-парсер, стабільність ID, граф залежностей, реєстри наданого експорту,
нативні шаблони JSON, ресурси PNG/моделі, транзакції ключів, інсталятор із
резервуванням/відкатом, Java-політику та компіляцію власного NeoForge JAR.
Мінімальний dev-сервер перевірив прив’язку основних ванільних mixin-цілей.
Реальні Mekanism/Create/AE2 на цьому сервері відсутні: їхні перехоплення
скомпільовано та звірено з вихідним кодом точних версій, але не зіграно.

Повний модпак, клієнтське завантаження ресурсів, мультиплеєрні ігрові
сценарії, продуктивність/TPS і довготривалий баланс не перевірено.
Немає підстав називати захист універсальним або гарантувати відсутність
усіх обходів у сотнях сторонніх модів.

Покриття Machine Guard:
- стандартний BlockEntityTicker: епоха блока та збережений власник-команда;
- ванільний результат 2x2/3x3, shift-click та Crafter до витрати ресурсів;
- окремий RecipeManager.getRecipeFor під час тіку блока, без глобального
  фільтрування списків рецептів/JEI; збережений власник потрібний також печам;
- Mekanism CachedRecipe.process до енергії та списання входів;
- Create Basin apply для змішування/компактування;
- AE2 Molecular Assembler через grid tick і окремий протокол термінала.
Стан додаткових Robit/brewing-адаптерів: compatibility-adapters-report.json.

Залишкові обмеження:
- власні кеші/глобальні процеси модів, contraptions, capability IO й деякі
  нестандартні меню не мають універсального перехоплення;
- пасивна броня/Curios та компоненти різних рівнів одного Item ID потребують
  окремих адаптерів; пряме використання предметів не покриває всі бонуси;
- ID з невідомого мода закриті, але кожен уже дозволений namespace/рівень
  ще потребує ігрового балансового аудиту;
- ритуали та спеціальні ресурси часто виробляються кодом мода поза
  RecipeManager. Відсутність у JSON-експорті не доводить недоступність;
- спостереження FTB підтверджує огляд указаного блока, а не його валідну
  мультиблокову форму або роботу; item task не є лічильником виробництва;
- 96 старих checkmark-цілей залишено для сумісності, до 2416 змістовних
  квестів їх не зараховано;
- ваші встановлені 50 глав/484 квести не були доступні повністю: базовий
  Git мав 48 глав/432 квести. Інсталятор зберігає інші глави й додаткові
  вузли, але невідому локальну редакцію треба перевірити після злиття.

Початкові стадії, відновлення ключа, зміна FTB-команди, офлайн-машини,
перезапуск, раннє виготовлення через автоматизацію та обмін предметами
між командами входять до обов’язкового приймального тестування інстансу.
Детальні джерела й сценарії: bypass-audit.json, native-adapter-review.json,
content/audit/quest-obtainability.json, validation-report.json.
