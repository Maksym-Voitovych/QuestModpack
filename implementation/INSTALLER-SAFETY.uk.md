# Безпечне встановлення AIA2

Закрийте Minecraft і сервер перед встановленням. Запустіть інсталятор із кореня розпакованого пакета або Git checkout. Python 3.9 або новіший:

```sh
python -m pip install nbtlib
python install_runtime.py "C:/CurseForge/AllInOneAdventure2" --dry-run
python install_runtime.py "C:/CurseForge/AllInOneAdventure2"
```

У Linux зазвичай використовується `python3`. Якщо всі конфігурації мають JSON-сумісний синтаксис, інсталятору достатньо стандартної бібліотеки. Для злиття вже збережених FTB файлів у SNBT потрібен `nbtlib`. Якщо залежності немає або документ неможливо безпечно прочитати, попередня перевірка завершується до будь-якої зміни інстансу. Інсталятор самостійно не встановлює залежності й не завантажує моди.

Підтримується SNBT, який пише редактор FTB Library 1.21.1: коментарі окремими рядками `#` та `//`, поля без ком, роздільник `=`, типізовані масиви й екрановані рядки. Вихідний контракт звірено з `SNBTParser.java` і `SNBTUtils.java` версії FTB Library 2101.1.37, [commit `ba8962d`](https://github.com/FTBTeam/FTB-Library/tree/ba8962d4b4dcff22041824c792fe07ae21fe28d5). Непідтримувані `End`/`null`-теги зупиняють інсталяцію для ручної міграції; вихідний файл залишається на місці.

Інсталятор виконує оновлення так:

1. Читає всі відібрані файли пакета й інстансу, перевіряє шляхи та готує злиття в пам’яті. `--dry-run` завершується тут, нічого не записуючи.
2. Зберігає **всі** файли, які буде замінено або прибрано, в `aia2-backups/<час>/original/`. Перевіряє байти резервних копій до першої заміни ігрового файла.
3. Записує кожен файл через тимчасовий файл у тій самій папці та атомарний `os.replace`. Журнал `aia2-backups/<час>/journal.json` містить список операцій і SHA-256 до/після оновлення.
4. Якщо операція завершується помилкою, відновлює всі вже змінені файли й старий AIA2 JAR та прибирає новостворені файли. Журнал отримує стан `rolled_back`. Якщо сам відкат не вдався, стан `rollback_incomplete` і повідомлення перелічують проблеми; резервні копії залишаються доступними.

Атомарність стосується окремого файла. Повне аварійне вимкнення процесу чи живлення між файлами не запускає Python-відкат: у такому випадку використайте журнал і `original/` для відновлення перед запуском гри. Інсталятор не створює резервну копію цілого світу.

Наявний `config/ftbquests/quests/data.snbt` зберігається байт у байт. Групи глав зливаються за стабільними ID: AIA2 оновлює власні групи, а сторонні залишаються. Невідомі квести всередині глав AIA2 також зберігаються за ID; невідомі файли глав не змінюються. Власні налаштування ProjectE зливаються, а `machineGuard.mode=required` не знижується.

З папки `mods/` пакета інсталятор бере тільки один `aia2-machine-guard-*.jar`. Під час зміни версії старі JAR із цим префіксом спочатку потрапляють до резервної копії, потім прибираються з інстансу, щоб не завантажувалися дві версії одного мода. Решта встановлених модів не змінюється. Світи, журнали прогресу команд/гравців і сторонні скрипти поза шляхами пакета не видаляються.

Папку інстансу можна вибрати через Windows Junction: спочатку вона перетворюється на фактичний шлях. Символічні посилання та вкладені junction у шляхах, які інсталятор має змінювати, відхиляються під час перевірки.

Після успішного встановлення повністю перезапустіть клієнт і сервер. `/reload` не завантажує нові startup-скрипти, предмети чи JAR.

Перевірка інсталятора:

```sh
python -m unittest discover -s tests -p test_installer.py -v
```

Тести перевіряють збереження 52 сторонніх квестів, сторонніх груп і типів SNBT, повторне встановлення, dry-run, повноту резервних копій, відмову при помилці читання джерела, відкат після заміни/міграції JAR та відхилення небезпечних шляхів. Тестування на файловій системі Linux не замінює перевірку конкретного Windows інстансу.
