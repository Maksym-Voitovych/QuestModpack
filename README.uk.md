# All in One Adventure 2.0 — 48 епох

Версія **0.3.0-alpha** для Minecraft 1.21.1 NeoForge, FTB Quests 2101.1.36, KubeJS 2101.7.2 і Rhino 2101.2.7 build.85.

Реалізовано **2512 квестів**: 2416 із перевірюваними ігровими завданнями та 96 збережених ручних цілей попередньої версії. Старі ID не змінено. Є 48 глав епох, модові глави у п’ятьох групах, 283 нативні рецепти, 48 серверних формул ключів, 192 виробничі компоненти й 293 текстури з моделями.

**Це робочий пакет для випробування, а не сертифікований реліз усієї збірки.** Повний Windows-інстанс, світи та JAR усіх модів у цьому середовищі відсутні. Перевірки реєстру, SNBT, графа, логіки, справжнього Rhino й компіляції адаптера відокремлено від тестування у Minecraft.

Виправлено причину помилок `global`: `AIA2Core`, `AIA2`, `AIA2Machines` створюються в `startup_scripts`; сервер оновлює вкладені властивості. `globalThis` у runtime не використовується. Після встановлення **повністю перезапустіть гру і сервер**.

Встановлення зі збереженням наявних файлів:

```powershell
git clone https://github.com/Maksym-Voitovych/QuestModpack.git
cd QuestModpack
python -m pip install nbtlib==2.0.4
python install_runtime.py "C:\CurseForge\AllInOneAdventure2" --dry-run
python install_runtime.py "C:\CurseForge\AllInOneAdventure2"
```

Перед встановленням закрийте гру й сервер. `H:\CurseForge\Instances\All in One Adventure 2.0` є Junction на той самий інстанс; встановлюйте один раз через основний шлях C. У Linux використовуйте `python3` та шлях до інстансу. Моди збірки вже мають бути встановлені. Інсталятор переносить тільки ігрові `kubejs/`, `config/` та власний JAR із `mods/`.

Спочатку інсталятор читає й готує всі зміни, потім резервує всі оригінали, після чого виконує атомарні заміни. За помилки відновлює змінені файли. Зберігає сторонні глави, групи, квести, світи, налаштування FTB і прогрес команд; старі версії лише власного Machine Guard мігрує через резервну копію. Для злиття справжнього SNBT потрібен `nbtlib`. Деталі: [безпека встановлення](implementation/INSTALLER-SAFETY.uk.md).

Перші перевірки в грі:

1. Перевірте відсутність помилок startup/server KubeJS і зображення ключів у JEI.
2. Виконайте `/aia2 status` та `/aia2 sync`; новому гравцю має бути доступна перша епоха.
3. Завершіть основні віхи, виробничу печатку та обов’язкові модові гілки. Біля звичайного верстака виконайте `/aia2 key`.
4. Перевірте, що відсутнє випробування чи матеріал блокує створення ключа без списання інвентарю. Перезапустіть сервер і перевірте збереження команди.

Ключ попередньої епохи витрачається тільки на наступний ключ. Предмет ключа сам по собі не видає стадію: сервер перевіряє журнал команди й квести перед транзакцією. Уже законно завершені епохи зберігаються; нові випробування застосовуються до наступних ключів. `/aia2 recover` платно відновлює останній законний ключ без нової стадії.

Система містить нативні item/kill/advancement/observation/dimension/stat завдання. Спостереження підтверджує огляд установленого блока, а предметне завдання — наявність або здачу предмета. Вони не заявляють вимірювання FE/t, топології мережі чи реальної кількості машинних циклів. Серед перевірок є чотири нативні докази операцій Create.

Рецепти поєднують Create, Mekanism, Botania, Oritech, Draconic Evolution та інші моди. Відомі дублікати матеріалів узгоджено з реальними виходами AlmostUnified. Нативні формули збережено у `kubejs/config/aia2_recipes.json`, а склад ключів — у `aia2_runtime.json` та інформації JEI.

AIA2 Machine Guard використовує власника FTB-команди, збереженого на машині. Окремі перехоплення перевіряють тік блока, ванільний крафт/Crafter, пошук рецепта під час тіку, кешовані рецепти Mekanism, Basin Create та крафт Molecular Assembler/термінала AE2. Це не універсальний аудит усіх процесів кожного мода; точні обмеження наведено у [звіті](implementation/KNOWN_LIMITATIONS.uk.txt).

Ресурси: 48 ключів із різними силуетами, 48 іконок епох, 5 розділів і 192 компоненти. [Огляд ключів](implementation/assets-preview.png), генератор `tools/generate_resources.py`. Зміна ілюстрацій не змінює ID предметів або прогрес.

Для розробника:

```sh
python -m pip install -r tools/test-requirements.txt
node --test tests/runtime.test.js tests/access-and-guard.test.js
python -m unittest discover -s tests -p 'test_*.py' -v
python tools/validate_game_pack.py
python companion/test_policy.py
```

Для Java-перевірок потрібен JDK 21. Тест справжнього Rhino потребує зовнішнього точного JAR/ядра та залежностей; відсутність позначається SKIP, а не успіхом. [Інструкція Rhino](tests/rhino/README.md). `companion/gradlew build` збирає нативний мод. Повторна генерація квестів і рецептів потребує оригінального експорту `export.7z`: `python tools/generate_game_pack.py --export-root /path/to/export`. Текстури генеруються окремо.
