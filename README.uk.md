# All in One Adventure 2.0 — 48 епох

Версія **0.4.7-alpha** для Minecraft 1.21.1 NeoForge, FTB Quests 2101.1.36, KubeJS 2101.7.2 і Rhino 2101.2.7 build.85.
Поточний блок додає45квестів Roots/AA/Apothic Enchanting/Spawners,3міжмодові рецепти AA та2командні докази завершення ритуалів. Новий native hook перевіряє просунуті руни до застосування. Типізований FTB/ProjectE міст, Machine Guard API4 і96виробничих ключів збережено. Повне0.5ще розробляється.


Hotfix виправляє неоднозначний FTB `getOrCreateTeamData`: типізований Java-міст явно обирає Entity overload і поточну команду гравця. UUID overload очікує UUID команди; `player.uuid` тут не є заміною. Встановіть новий JAR разом зі скриптами й повністю перезапустіть гру/сервер. Розробка 0.5 ще триває: [план](docs/AIA2_0.5.0_PLAN.md), [прогрес](docs/AIA2_0.5.0_PROGRESS.md).

Головна зміна — два справжні виробничі ключі кожної епохи: технологічний і магічно-дослідницький. Наступна епоха відкривається після обох обов’язкових гілок, виготовлення обох ключів і завершення фінального квесту. Старі артефакти епох, їхні ID та законно завершений командний прогрес збережено.

Версія містить **3261 квест у 139 главах**, з них 3165 змістовних і 96 старих ручних цілей, залишених для сумісності. Поточний блок розробки 0.5 додав477 квестів і46 нових або перероблених рецептів; попередні предмети та ресурси збережено. Загалом —615нативних рецептів, 48 серверних формул гравіювання та 390 власних предметів/PNG. Деталі й результати перевірок наведено у [звіті релізу](implementation/release-report.json). Групи: **Епохи, Технології, Магія, Пригоди, Колекції, Автоматизація**.

У Machine Guard виправлено підтверджені помилки Java/Rhino. Метод `getUUID()` у KubeJS перейменовано на `getUuid()`, а `uuid` є властивістю, не функцією. Тепер скрипт передає справжнього `ServerPlayer` у типізований Java-метод, який отримує UUID безпосередньо. Ініціалізація починається після першого тіку, коли FTB Quests уже завантажив файли. Тимчасова неготовність має обмежені повторні спроби; пошкоджені правила чи журнал залишають захист закритим і показують причину.

ProjectE використовує окремий Java-міст із єдиною сигнатурою `long`: звичайний `put` і навіть явне `Long.valueOf` були неоднозначними у справжньому Rhino build.85. За помилки whitelist EMC закривається, а помилка залишається видимою. Деталі: [аудит](implementation/guard-v4-audit.json).

Для встановлення закрийте гру й сервер, оновіть локальний Git-репозиторій зі збереженням власних правок або розпакуйте GitHub ZIP в окрему папку. Не застосовуйте старі виправлення `uuid()` поверх нових скриптів. Не використовуйте `git reset --hard` для усунення конфліктів.

```powershell
cd "C:\Users\Maximus\Desktop\CodexQUESTS\QuestModpack"
python -m pip install nbtlib==2.0.4
python install_runtime.py "C:\CurseForge\AllInOneAdventure2" --dry-run
python install_runtime.py "C:\CurseForge\AllInOneAdventure2"
```

Інсталятор спочатку готує всі зміни й резервує оригінали, а потім виконує атомарні заміни. Він зберігає світи, дані команд, сторонні глави й додаткові квести. Старий власний `aia2-machine-guard-0.3.0-alpha.jar` мігрує через backup; сторонні моди не видаляються. Шлях Junction H веде до того самого інстансу, тому встановлювати потрібно лише один раз через C. [Порядок встановлення](implementation/INSTALL.uk.txt), [резервування та відкат](implementation/INSTALLER-SAFETY.uk.md).

Оновлюйте JAR і скрипти разом. Після встановлення **повністю перезапустіть гру й сервер**: `/reload` не замінює завантажений Java-мод і не реєструє нові startup-предмети.

Після запуску виконайте `/aia2 status`. Готовий захист показує **API 4**, кількість правил та активний стан. У разі помилки видно фазу і причину. Після усунення причини оператор може виконати `/aia2 guard retry`; це не відкриває епохи й не скидає прогрес. Якщо встановлено неправильний JAR, потрібні його заміна та повний перезапуск.

Проходження нової епохи:

1. Завершіть обов’язкову технологічну та магічно-дослідницьку гілки.
2. Виготовте кожен із двох ключів за рецептом JEI. Нативний захист дозволяє рецепт відповідної гілки після її завершення.
3. Дочекайтеся зарахування виробничих квестів. Сервер зберігає запис успішного виконання рецепта після витрати матеріалів. `/give`, Creative-вкладка чи передача іншої команди такого запису не створюють.
4. Біля звичайного верстака виконайте `/aia2 key`: фінальне гравіювання витрачає обидва ключі та попередній артефакт. Для епохи 1 попередній артефакт замінено звичайним верстаком.
5. Завершіть фінальний квест переходу. Лише після його підтвердження й виробничих умов сервер зберігає завершення епохи та відкриває наступну стадію.

У перших трьох епохах обидва ключі виготовляються вручну. Далі технологічна гілка використовує Create Mixer, а з епохи 16 — Metallurgic Infuser Mekanism; магічний ключ карбується через Create Compacting. Входи проходять власні промислові, магічні, ритуальні й пізні fusion-ланцюги. Точні рецепти не приховані за безкоштовною командною видачею.

`/aia2 recover` відновлює лише останній уже законний артефакт за попередньою платною формулою, без нової стадії. Завершені у 0.3 епохи не потребують повторного проходження. Нові подвійні умови застосовуються до наступного незавершеного переходу. [Механіка та міграція](design/progression-v4.md).

Квести на огляд блока перевіряють фактичний огляд установленого блока. Вони не вимірюють потужність, коректність усієї мережі чи число циклів. Виробничі записи для двох ключів є окремою нативною перевіркою. Необов’язкові курси автоматизації поглиблюють моди й не створюють додаткової прихованої перепони для старих епох.

Команди перевірки для розробника:

```sh
python -m pip install -r tools/test-requirements.txt
node --test tests/*.test.js
python -m unittest discover -s tests -p 'test_*.py' -v
python tools/validate_game_pack.py
python companion/test_policy.py
```

Java-перевірки потребують JDK 21. Реальний Rhino-тест потребує точного зовнішнього ядра й залежностей; відсутність позначається **SKIP**, а не успіхом. [Інструкція](tests/rhino/README.md). Нативний мод збирається через `companion/gradlew build`. Для повторної генерації рецептів і квестів потрібен початковий експорт: `python tools/generate_game_pack.py --export-root /path/to/export`. Генератори ресурсів: `tools/generate_resources.py` та `tools/generate_dual_key_resources.py`.

Нативний smoke-test виконав **49 перевірок у двох справжніх серверних JVM**, включно з блокуванням печей/Crafter, виробничим доказом та його відновленням після перезапуску. Для цього використано ванільну модель рецепта ключа; самі KubeJS-предмети й FTB у мінімальному сервері відсутні.
